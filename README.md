# Calibra
**The memory layer for consistent human judgment.**

Two legal-editorial reviewers, Priya and Arjun, have each built up an
unwritten evaluation style over years of grading submissions — Priya
weighs citation precision heavily, Arjun weighs original argument over
citation mechanics. Calibra remembers each reviewer's pattern in its own
Hindsight memory bank, and for any new submission predicts how *each*
reviewer would score it — flagging and explaining where they'd disagree,
before a human ever has to catch the inconsistency.

This is not "an agent that learns your preferences." It's memory used as
an **inter-rater calibration layer** — surfacing disagreement between
people, which is the real, underserved problem in any organization with
distributed human graders (legal, publishing, academia, hiring).

## How Hindsight is used
- One memory bank per reviewer (`reviewer-priya`, `reviewer-arjun`)
- `retain()` — every past review comment/pattern is stored as a memory
- `recall()` — before predicting a score, Calibra recalls the memories
  most relevant to the new submission, and shows them in the UI as
  "what this is grounded in"
- The predicted score/feedback is generated by an LLM (Groq) that is
  **only** allowed to draw on recalled memories — not free-invented taste
- **The loop closes with `retain_outcome()`**: when you tell Calibra what
  a reviewer actually scored a submission, that outcome is written back
  into the reviewer's bank as a new memory. The next prediction for a
  similar submission recalls it alongside the seed history, so the
  system visibly sharpens after real use — this is what turns the demo
  from "smart lookup" into "learning agent."

## Setup (few-hours version)

1. **Get a Hindsight Cloud key**
   Sign up at https://ui.hindsight.vectorize.io, create an org + API
   key. Add promo code `MEMHACK99` in the billing section for $50 free
   credit.

2. **Get a Groq key**
   https://groq.com — free tier, use `openai/gpt-oss-120b`.

3. **Configure**
   ```bash
   cp .env.example .env
   # fill in HINDSIGHT_API_KEY and GROQ_API_KEY in .env
   ```

4. **Install**
   ```bash
   pip install -r requirements.txt
   ```

5. **Seed reviewer memory** (run once)
   ```bash
   python seed.py
   ```
   This pushes each reviewer's past-review history into their own
   Hindsight bank. You should see "Seeding complete" at the end.

6. **Run**
   ```bash
   python app.py
   ```
   Open http://localhost:5050

7. **Demo — the sequence to actually run on camera**
   This sequence is built to hit the judging criteria directly, in order:

   1. Point at the three-line pitch strip under the title for two
      seconds before touching anything — problem, what memory does,
      who pays — so judges have the business frame before they see any
      UI. This is your Real-world-Impact (10%) line landing early
      instead of being buried at the end.
   2. Click **"Memo on force majeure clauses post-pandemic"** → Predict.
      Both reviewers agree-ish, low drama. This is your baseline.
   3. Click **"Note on arbitral seat vs venue distinction"** → Predict.
      Priya scores it lower (citation mechanics), Arjun scores it higher
      (original argument) — the disagreement banner fires and explains
      *why*, citing the specific recalled memories driving each score.
      **This is your Use-of-Hindsight-Memory (25%) and Innovation (30%)
      moment** — say out loud that this isn't personalization, it's
      catching disagreement between two humans before it reaches a
      student.
   4. Click **"Reflect: synthesize Priya's fingerprint"** under her
      column. This calls Hindsight's `reflect()` — a different primitive
      from the `recall()` you just saw — and shows a synthesized
      paragraph of her evaluation style, not a retrieved snippet. Say
      out loud that this is the difference between lookup and synthesis.
   5. Under Priya's column, enter what she "actually" scored the seat/
      venue note (lower than predicted) and a one-line reason, click
      **Record outcome**. Watch her memory count tick up on screen.
   6. Click **"Follow-up: seat vs venue in maritime arbitration"** →
      Predict. Same citation pattern as step 3. Priya's new prediction
      should now visibly reflect the outcome you just recorded —
      narrate this as the "review #1 → review #5" learning curve the
      brief asks for, compressed into under a minute.
   7. Click Priya's fingerprint button again. The synthesized paragraph
      should now read differently than it did in step 4 — this is the
      single clearest "the agent learned" moment in the whole demo,
      because it's Hindsight's own synthesis changing, not just a new
      retrieved line.
   8. Close with the memory count and grounding panel still on screen —
      it's your receipt that every number came from retained memory,
      not a static rubric.

   **If wifi or an API hiccups mid-demo:** every call is wrapped so a
   failure shows a short, calm message in that one card instead of
   crashing the page — keep talking, click the seeded example again, it
   recovers on its own.

## Files
- `app.py` — Flask routes (`/`, `/api/predict`)
- `memory_bank.py` — Hindsight wrapper (bank per reviewer, retain/recall/reflect)
- `groq_client.py` — LLM wrapper, grounds every prediction in recalled memories
- `seed_data.py` — synthetic-but-realistic reviewer history + demo submissions
- `seed.py` — one-time script to push seed data into Hindsight
- `templates/index.html`, `static/style.css` — the demo UI

## If you have more time later

  submissions from your legal-editorial program, anonymized

  read the count back from Hindsight instead of tracking it locally
- `safe_call()` in `app.py` currently degrades every failure the same
  way; if you want to distinguish "Hindsight is down" from "Groq is
  down" in the UI, pass a `kind` through the fallback instead of just a
  string message
